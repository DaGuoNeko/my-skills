---

## 为什么需要这个 Skill

当前主对话模型（如 glm-5.2、Claude 3.5 Sonnet 等）**不支持图像输入**。直接调用 `mcp__mcdk_game__capture_game_window` 截图工具时，返回的 base64 图像数据会被丢弃，只得到一行：

```
[Media omitted from provider request because the selected model does not support image input.]
```

也就是说，**主模型直接调用截图工具 = 白截，什么都看不到。**

## 核心方法：委托 Kimi 子 agent 读图

Kimi agent 背后是多模态模型，支持原生图像输入。把截图任务委托给它，它就能真正"看到"画面。

### 操作步骤

1. 用 Agent 工具，指定 `subagent_type: "Kimi"`
2. 在 prompt 中让 Kimi 调用 `mcp__mcdk_game__capture_game_window` 截图
3. Kimi 拿到图像后，用视觉能力直接读取并返回描述

### 完整调用示例

```
Agent 工具参数：
  description: "Kimi读取游戏截图"
  subagent_type: "Kimi"
  prompt: |
    请调用 mcp__mcdk_game__capture_game_window 工具（无需参数）截取当前运行的
    Minecraft 基岩版游戏窗口画面。该工具会返回一张 480p JPEG 截图。

    收到截图后，请基于你的多模态视觉能力直接观察这张图片，详细描述画面内容，包括：
    1. 当前显示的是什么界面（游戏内场景 / 菜单 / UI 面板等）
    2. 画面中所有可见的文字内容（逐字记录）
    3. UI 元素的布局、颜色、图标
    4. 如果是游戏场景，描述场景中的实体、方块、玩家状态等

    请用中文返回详细的画面描述。如果截图调用失败，请报告具体错误信息。
```

### 关键参数说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `subagent_type` | `"Kimi"` | **必须**。指定 Kimi 多模态 agent |
| `prompt` | 见上方示例 | 让 Kimi 自己调用截图工具并描述画面 |
| `model` | 不填 | Kimi agent 有自己的默认多模态模型 |

> ⚠️ **不要**在主模型中先调用 `capture_game_window` 再把结果传给 Kimi --主模型拿到的图像会被丢弃，传过去的只是 `[Media omitted...]` 文本。**截图必须由 Kimi agent 自己调用工具完成。**

## 适用场景

| 场景 | 用本 Skill | 用 jsonui_debugger |
|------|-----------|-------------------|
| 排查颜色 / 贴图 / 图标显示 | ✅ 直接看 | ❌ 读不到 |
| 排查布局错位 / 元素重叠 | ✅ 直接看 | ⚠️ 只能推断 |
| 排查游戏场景（方块、实体、手持物品） | ✅ 直接看 | ❌ 读不到 |
| 读取 UI 文字内容 | ✅ 直接看 | ✅ 也能读，但需多次调用 |
| 验证 JSON UI 结构绑定 | ⚠️ 只能看外观 | ✅ 更精准 |

## 前置条件

1. 游戏通过 MCDK 启动，`.mcdev.json` 中 `mcp_server_config.enabled: true`
2. `mcdk_stdio_bridge.py` 已注册为 MCP Server（名字 `mcdk_game`）
3. 游戏已进入世界
4. **已注册 Kimi 多模态 agent**（见下方说明）

### 注册 Kimi agent（仅首次需要）

Kimi agent 不是 ZCode 内置的，是用户级自定义 agent。如果调用时报错：

```
Agent type '"Kimi"' not found. Available agents: general-purpose, Explore
```

说明当前环境没注册 Kimi agent。需要创建 agent 定义文件：

**文件路径**：`~/.zcode/agents/kimi.md`（Windows 为 `C:/Users/<用户名>/.zcode/agents/kimi.md`）

**文件内容**：

```markdown
---
name: "Kimi"
description: "专用于图像输入分析，不响应任何纯文本对话。基于原生多模态能力，自动提取截图、图表或界面中的视觉信息，并转化为结构化描述或可执行的动作指令。若当前环境可连接 Minecraft 基岩版游戏（mcp__mcdk_game 工具可用），可自行调用 mcp__mcdk_game__capture_game_window 截取游戏画面并分析。"
color: purple
model: "custom:859b1b02-ece0-4baa-a12b-fc965686a03c:kimi-k2.7-code"
---

# 角色定义
你是一个视觉感知与代码转译专家。你的核心职能是接收并解析图片输入，将视觉信息转化为结构化的技术描述或可执行的动作指令。当没有图片输入但需要查看游戏画面时，你可自行调用截图工具获取画面。

# 核心边界（极其重要）
1. 输入处理规则：
   - 有图片输入：直接解析图片内容。
   - 无图片输入但 mcp__mcdk_game__capture_game_window 工具可用：调用该工具（无需参数）截取当前 Minecraft 基岩版游戏窗口画面，收到截图后按正常流程分析。截图工具返回的是 480p JPEG 图像，你可用多模态能力直接观察。
   - 无图片输入且截图工具不可用：直接回复："[系统拒绝] 本节点仅处理图像输入，请提供需解析的图片。"
2. 拒绝记忆依赖：忽略此条消息之前的所有历史对话记录。你的分析仅基于当前消息中附带的图片内容或自行截取的游戏画面。
3. 拒绝发散回答：不要对图片内容进行艺术评价、情感分析或超出技术实现层面的泛化讨论。

# 工作流与输出规则
当接收到图片时，请按以下四步处理：
1. 元素识别：提取图片中的所有关键视觉元素（如：UI控件、数据图表线条、代码报错红框、流程图节点）。
2. 意图推断：判断这张图最可能的诉求（是"找Bug"、"转代码"、"数据提取"还是"流程梳理"）。
3. 结构化输出：根据意图，输出纯技术性的JSON格式结果或带有明确逻辑步骤的文本。
4. 知识补充：如果图片内容涉及特定框架（如React、Vue、Python），在输出末尾提供不超过3行的"技术方案推测"。

# 输出格式模板
请严格按照以下格式返回：
---
**【图像主题】**：[一句话概括图片核心内容]
**【关键要素】**：[用列表列举识别到的核心数据/控件/文本]
**【执行建议】**：[基于视觉分析，给出具体的操作代码、修复步骤或数据表格]
**【风险提示】**：[仅当发现图片中存在明显逻辑或视觉冲突时填写此项]
---

# 异常处理
- 如果图片模糊或关键信息被遮挡，请输出："[需补充] 图像关键区域模糊，请确认后重传。"
- 如果图片非技术类（如风景、人物自拍），请输出："[超出范围] 本智能体仅限技术类图像解析。"
```

> **注意**：`model` 字段的值 `custom:859b1b02-...:kimi-k2.7-code` 是当前环境配置的 Kimi 多模态模型 ID。如果你的 ZCode 环境配置了不同的多模态模型（如 Gemini、GPT-4o 等），将 `model` 改为对应模型 ID 即可，agent 逻辑本身通用。创建后重启 ZCode 会话即可生效。

### 如果没有多模态模型可用

若当前环境完全没有任何支持图像输入的模型，Kimi agent 无法工作。此时只能用 `jsonui_debugger` 逐节点解析 UI 结构树间接获取界面文字信息（但看不到颜色、图标、背景场景）。

## 三种读图方式对比

| 方式 | 能看图？ | 能看背景场景？ | 工具调用次数 | 适用场景 |
|------|---------|--------------|------------|---------|
| 主模型直接截图 | ❌ 图像被丢弃 | ❌ | 1 | 不可用 |
| sonnet agent + jsonui_debugger | ❌ 绕道解析结构树 | ❌ | ~40+ | 只需文字内容时 |
| **Kimi agent 截图（本 Skill）** | ✅ 真正视觉识别 | ✅ | 1 | 需要视觉验证时 |

## 限制

- 截图分辨率为 480p，细小文字可能模糊
- Kimi 返回的是文字描述，不会返回图像文件本身
- 如果游戏卡死或未聚焦，截图可能异常
